# Tracked delivery

Use the existing Kanban lifecycle for a deliverable that needs independent acceptance.

1. Reuse the current goal and any matching card. Record the board slug and card ID in the goal session, and retain the native notification subscription to that session. A dependency link alone does not associate work with a goal. Reopening Work restores a view; dispatch only through the existing native eligibility and claim path.
2. Before dispatch, agree on observable outputs and acceptance checks within the owner scope. Declare `required_artifacts` as exact relative file names and `acceptance_criteria` as a map from each declared check ID to its success condition in the existing version-1 `hermes-contract`. Set `require_review` to true. Retain the normal hashed inputs, environment and check definitions. Use the evidence format below; never invent hashes or test receipts. If the installed runtime does not support this contract, keep acceptance pending and report the capability gap.
3. Choose an eligible implementation profile and a different eligible review profile using the existing role-routing policy. Keep budgets, authorized provider routes and write scopes. The implementer produces the outputs, runs the declared checks, and calls `kanban_request_review` with current artifacts and verification. Its prose summary does not certify delivery.
4. The reviewer reads the current brief and handoff, inspects the required outputs, and independently runs the declared checks. On success, use the `metadata.delivery_review` record provided by the current native worker context, plus current verification and artifacts, in `kanban_complete`. The native gate binds acceptance to that handoff, reviewer run, brief and output hashes. Changed requirements or outputs need a fresh implementation handoff.
5. For a correctable defect, request changes on the same card with the failed criterion, evidence and bounded remedy. The implementer revises and submits a fresh handoff. For missing input, authority or an unavailable dependency, block with the concrete reason and the smallest decision needed; preserve the held card rather than creating a duplicate.
6. Deliver only after native acceptance succeeds and all required work in the owner scope is finished. Report the artifact, criteria checked and review evidence. Distinguish evidence accepted at handoff from any fresh runtime or visual verification still required. Legacy `done` cards remain historical completions, not verified deliveries.

A read, restart or repeated notification is not a new work order. Follow native events or bounded non-model waits; keep unchanged waits quiet. These instructions add no model calls solely for polling, no new permissions, and no waiver of owner holds or publication gates.

## Contract and evidence format

Put one fenced `hermes-contract` JSON object in the task body. Its version is `1`. Declare `checks` as unique check IDs, `inputs` and `environment` as path-to-SHA-256 maps, and `check_definitions` as check-ID-to-script-path entries. Every script must also appear in hashed inputs. Add `acceptance_criteria` with exactly those check IDs, `required_artifacts` with the relative output paths, and `require_review: true`. Keep the plain-language objective and scope outside the fence.

At handoff, `metadata.artifacts` lists the produced relative paths. `metadata.verification` has version `1`, the current native `run_id`, the same `inputs`, `environment` and `check_definitions` maps, and a `checks` array. Each recorded check includes `name`, actual `exit_code`, relative `log`, that log's `sha256`, and numeric Unix-second `completed_at` and `expires_at`. Record `completed_at` after the current native run started; a previous attempt or reviewer record cannot be reused. Set a bounded validity period appropriate to the check. Generate this record from the actual command and bytes; writing a successful exit code is not running a check. The reviewer's evidence comes from its own execution. The native reader validates the declared bytes and records; it does not independently execute those commands or establish universal correctness.
