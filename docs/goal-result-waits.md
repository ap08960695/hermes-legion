# Rejudge completed work during advisory card waits

A goal can park for 15 minutes while its subscribed Kanban work runs. Previously,
a genuine new assistant turn could process the finished result, yet the goal
manager still skipped gates and judging until the old timer expired. This
stalled follow-on work even though the native notification had already arrived.

Judge-created time waits now record only the number of pending cards at creation.
Successful native CLI, TUI, Gateway and classic-viewer post-turn hooks explicitly
request re-evaluation. A new completed turn may clear that advisory timer, then
normal quality gates, judging and turn limits decide whether to continue, wait
again, pause or finish. The card count never proves delivery, completion or ACK.
No extra model request is generated by an idle check, and a missing database row
does not release the timer. No new polling, replay or provider fallback is added.

Explicit owner time waits, live PID waits, process-session waits and judge waits
without followed cards retain their existing behavior. Legacy saved waits have
no origin marker and safely retain their previous deadline. Existing delegation
result handling, failure/interrupt guards and terminal-goal suppression remain.
The marker stores no route, task ID, prompt, credentials or conversation content.

The classic viewer also passes the server-owned live notification destination to
the goal counter. Platform, chat, thread and runtime profile come from the
already-authorized native session; client-supplied destination kwargs are ignored.
The existing session-control authorization and single-owner judging remain.

## Verification and limits

The original four successful post-turn surfaces reproduced the stalled judgment,
with three independent-wait/passive controls passing. The final related selection
passes 302 cases in 30 files, zero failures and file retries. Additional controls
cover saved-state compatibility, passive quiet, remaining-work re-parking,
quality-gate failures, turn limits, neighboring routes and late duplicate turns.
An older route test incorrectly called the successful post-turn hook to simulate
an idle poll; it now uses the actual passive manager check. The authority fixture
binds the real native route helper as its runner contract now requires.

Linux and macOS production Python each verify nine installed-source scenarios
using real isolated SQLite tasks, owned claims and terminal runs. The actual
post-turn hooks execute with a controlled judge and controlled failing gate; no
provider or model is called. In these fixtures a processed result is rejudged
with over 800 seconds left on the fallback timer, while passive checks add zero
judge calls. This is deterministic avoided waiting, not measured production
throughput, billing savings or original-session adoption.

Both hosts verify the full public patch and source parity. Linux source activation
requires native idle-only acknowledgement; the original macOS Gateway remains
off. Models, effort ceilings, quota, credentials, fallback rules, emergency stops,
review/publication gates and active-worker ownership are preserved. This repair
needs no Desktop renderer rebuild. Continuous autonomous multi-bot graph proof
and representative usage/cache measurements remain separate work. Historical
selections overlap and are never summed; the previously documented twenty
inherited auxiliary failures are not claimed fixed by this selection.
