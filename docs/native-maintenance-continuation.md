# Native continuation and verified maintenance retirement

This evidence-only update adds no runtime patch, provider route, dependency, Desktop package, permission default or timer change. The installed Linux and Mac source payload remains the same 974-path kit as v0.8.25.

## Automatic review and revision

One fresh simple arithmetic card ran through the private native Gateway with automatic Kanban dispatch enabled. The fixture seeded the card once; its driver then read evidence and never called the dispatcher or advanced a lifecycle transition. The initial draft intentionally lacked the required newline. A different reviewer rejected it, the implementer corrected it, and the reviewer accepted the current output.

The first reviewer also posted a comment before requesting changes. The fixture recorded no transport failure, task retry or provider fallback. All four attempts were on the same card, with at most one worker at a time, a 20-request total ceiling and five-request per-attempt ceiling. Each used the existing authorized model at low effort. Native run records span 72 seconds from first start to acceptance.

The four worker sessions recorded 178,614 total prompt tokens, including 135,040 cache-read tokens, plus 1,515 output tokens. Native canonical accounting stores uncached input separately; the prompt total here sums uncached, cache-read and cache-write buckets. These are observations from this case, without a before/after workload or billing comparison.

The accepted receipt binds the revised implementation handoff to the final independent reviewer run. The output bytes are exactly `5\n`. Repeated delivery reads caused no request or run. A further five-second observation, spanning several private dispatch ticks, saw no new request or duplicate dispatch. The private Gateway then stopped. Linux GPU devices were unavailable and production settings, holds and Gateway were preserved.

This proves bounded automatic dispatch and review/revision continuation for this simple card. It does not establish unrestricted autonomous planning, production Captain adoption, sustained parallel throughput, or a general usage-saving estimate.

## Retired maintenance copies

Selected completed test snapshots and duplicate release exports/readbacks were retired after checking file inventories, hashes, metadata, native unfinished-card workspace references and process holders. Canonical release archives, source rollback files, original card evidence, settings, credentials and held work remain intact. Database snapshots and their sidecars were preserved byte-for-byte in verified private compressed archives before removal.

The figures count the selected files/directories and their replacement evidence archives. They are not an attribution of a filesystem-wide free-space change; unrelated writers, filesystem snapshots and block sharing can affect that measurement. Small new operational receipts are outside this selected-byte calculation.

Normal-user observation could not see every protected system/SSH process. A read-only privileged observer obtained complete identities and holder information for the selected scope; deletion ran as the file owner. A process appearing during the initial Linux scan stopped retirement, preserving all remaining originals. Fresh complete observation resumed the remaining actions without repeating those already completed. Missing visibility still means retain; the distributed retention helper's guard remains in place.

Linux's 413 protected files and Mac's 77 protected files were unchanged. The Linux production Gateway remained idle at its original identity, and the Mac production Gateway stayed stopped. Raw snapshots, local paths, task/account identities, transcripts and operational receipts are not included in this public report.
